# Handoff: Claude chat tab (2026-10-30)

Discuss with the user in Vietnamese; code and comments in English. All new UI goes through templates
(`crates/tern-app/src/templates.json` + elements in `style.rs`), behavior attached by `frame`/`button` names.

## Task

The user asked to copy Orca's "native chat" into Tern, with rendering modelled on T3 Code. A chat tab
drives the real `claude` CLI headless (stream-json), not the Agent SDK, so settings, hooks, MCP, skills,
login and CLAUDE.md are the same as in a terminal tab. Reference material:
- Orca: `../refs/orca/src/main/claude/` (protocol), `src/renderer/src/components/native-chat/` (UI).
- T3 Code: `~/ws/t3code` is an empty, broken clone. The render study came from
  `/Applications/T3 Code (Beta).app` (minified bundle).

## Done (uncommitted; the working tree also holds other unrelated uncommitted work)

### Phase 1: the chat UI
- **`crates/tern-chat/`** (new crate).
  - `transcript.rs`: folds stream-json frames into `Entry`s (User, Text, Thinking, Tool, Ask, Notice, TurnEnd).
  - The fold covers streaming deltas, tool results, `can_use_tool` requests, `initialize` replies (commands,
    models, current mode) and replayed `control_response`s.
  - `load_before(path, ms)` reads Claude's saved `.jsonl`, with turn durations taken from the timestamps.
  - `launch.rs`: `Launch::args()`, `PermissionMode` (Default/AcceptEdits/Plan/Auto/Bypass),
    `transcript_path`, `new_session_id`, and `wire::*` builders for the lines written to stdin
    (initialize, user, answer, interrupt, set_permission_mode, set_model).
  - `summary.rs`: tool labels, group summaries ("Ran 1 command, edited 2 files"), durations, details.
- **`crates/tern-app/src/chat_view.rs`**: `ChatView`.
  - Rows: user bubble; markdown reply (`TextView::markdown`); tool and group rows; thinking;
    "Worked for Xs" fold; "Working for Xs"; notices; ask cards (Allow / Allow for this session / Deny,
    AskUserQuestion options, ExitPlanMode plan).
  - The list is gpui-component's `MessageScroller`; rows are spliced from the first changed signature.
  - The input is a `Textarea` with `submit_on_enter`; there is a permission-mode button and Stop.
- **Templates and elements:** `chat`, `chat.empty`, `chat.composer`, `chat.user`, `chat.text`,
  `chat.tool`, `chat.group`, `chat.thinking`, `chat.worked`, `chat.working`, `chat.notice`, `chat.ask`.
  The slot `markdown` was added to `template/mod.rs` SLOTS, and the icons Brain and Sparkles to `file_icons.rs`.
- **Workspace:**
  - `CenterTab::Chat` and the action `workspace::NewClaudeChat` (palette, File menu, + menu).
  - `SavedTab::Chat { session, account, mux }`.
  - `claude_env` and `tern_mcp_config` were extracted from `spawn_config` and are shared with terminal tabs.
- **Control socket** (debug): `chat-new`, `chat-open ID`, `chat-send TEXT`, `chat-state`,
  `chat-answer allow|session|deny`, `chat-mode MODE`.

### Phase 2: chats run in the daemon
- **`crates/tern-mux/src/chat.rs`**: `ChatHost`, the piped process.
  - The reader is poll-based with a wake pipe, so it can `park()` for a handoff.
  - It keeps a replay log: stream deltas are dropped once their turn's `result` arrives; client
    `control_response` lines are kept.
  - It posts notifications while no UI is connected.
- **Protocol:** MINOR 12 (`CHAT_MINOR`), HANDOFF_VERSION 5.
  - `SpawnChat`, `AttachChat`, `ChatInput`, `DetachChat`, `CloseChat`.
  - `ChatAttached{started, lines, exited}`, `ChatLine`, `ChatExited`.
  - Handoff sends `HandoffMsg::Chat` with the stdin, stdout and stderr fds.
- **Server:** `State.chats`, idle accounting, and detaching when a connection goes.
- **Client:** `client::RemoteChat` and `MuxClient::open_chat`.
- **ChatView's flow:**
  - It connects off the UI thread. An older daemon is handed off automatically via `Connector::hand_off`.
  - On attach it replays: history saved before `started`, then the daemon's lines.
  - `Lost` reattaches; `NotFound` falls back to resuming with `--resume` on the next message.
  - Closing the tab ends Claude; dropping the tab (app quits) detaches and Claude keeps running.
- **Tests** (all pass, along with fmt and clippy `-D warnings`):
  - unit tests in `chat.rs`;
  - `tests/daemon.rs::chats_run_on_without_a_tab`;
  - `tests/handoff.rs::a_running_chat_moves_to_the_new_daemon`.

### Phase 3 (second session, same day)
- **Claude starts early:** when the message box takes focus or the user types (`ChatView::warm`), not at
  the first message, so its commands and models are known. `live` says a program was asked for and hasn't
  ended (it replaces the `chat.is_none() && chat_id.is_none()` test, which started a second one while
  the first was still connecting).
- **Slash commands:** typing `/` (no space yet) lists `Transcript.commands` over the text (`chat.commands`
  template, elements `chat.commands`, `chat.commands.row`, `chat.commands.note`), those starting with the
  query first (`command_matches`, unit-tested), 8 rows at a time. Up/Down move, Tab puts `/name ` in the
  box, Enter does too unless the command is typed out already (then it sends), Escape hides the list
  until the text changes, a click picks. The keys are `capture_action`s on the `chat` frame.
- **Model picker:** the composer's model button is a dropdown (`menu.chat_model`, element `chat.model`)
  of `Transcript.models`; a pick writes `wire::set_model` and is kept in `model_picked`, passed as
  `--model` when Claude is started anew. The label: the picked model, else `Transcript.model`, else the
  `default` entry's name. Checked: picking Sonnet made the next turn run `claude-sonnet-5-5`.
- **Multi-select questions:** a `multiSelect` question's options toggle ("Choose any"), and a card with
  one waits for Submit (disabled until every question has a pick). The answer is a list of labels for
  such a question (what `claude` 2.1.314 validates: a string or, for multiSelect, an array), a string
  otherwise. Picked options are drawn as secondary buttons with a check. Checked end to end.
- `chat-state` now also prints `live`, `picked`, the command and model counts and the slash matches.

### Phase 5 (third session, same day)
- **In-app notifications:** a chat tab reaching Done or Blocked while its window is inactive or the tab isn't
  shown posts a system notification (`ChatEvent::Status` in `Workspace::add_chat`; `tern_term::status::status_notification`,
  titled by the chat's title via `task_name`). `is_shown` became `tab_shown(EntityId)` for any tab. Chat tabs have
  no mute yet. Not seen live (the check used a full-screen capture, which isn't acceptable: the user's screen).
- **Thumbnails in sent messages:** `Entry::User.images` is `Vec<UserImage>` (media type + decoded bytes, from the
  base64 `image` blocks of the stream and of the saved `.jsonl`; a custom `Debug` keeps row signatures cheap).
  `ChatView.thumbs` caches one `gpui::Image` per image, keyed by the bytes' address (the cache holds the bytes,
  so an address isn't reused). Template `chat.user` draws them over the bubble (elements `chat.user.images`,
  `chat.user.image`); the bubble is hidden for an image-only message. Checked live: pasted image, sent, shown;
  reopened from the saved history, shown again. Unit test `a_saved_message_keeps_its_images`.

- **Mute for chat tabs:** `CenterTab::Chat { muted }` (`CenterTab::muted()`), the tab menu's Mute/Unmute

  chat (`ChatHost::set_muted`, not handed off); `ChatView` emits `ChatEvent::Chat` on every attach, so the tab says
  its mute again to a new daemon. Test `a_muted_chat_posts_nothing`. Mute/Unmute clicked through in the menu.

- **Row spacing:** gpui-component's `MessageScroller` adds `pb_8` under every row and `px_3`; the chat's rows space
  themselves in their templates, so `with_row_style(px_0, pb_0)` drops those (tool rows were ~60px apart), and

- **File-change request card, seen live:** a scratch project with `.claude/settings.local.json`
  `{"permissions":{"ask":["Edit","Write","MultiEdit"]}}` (ask beats the user's allow) in "Ask first" mode made Claude ask;
  the card shows the diff; Allow edited the file, Deny left it and Claude said so. Fixed on the way: a closed group's
  summary counted the tool still running under it ("Edited 1 file" while it waited); `ChatView::running_apart`
  now decides both the row shown apart and what the summary leaves out.
- **Notification, confirmed in the system log** (`/usr/bin/log show --predicate 'eventMessage CONTAINS "dev.tern.debug"'`):
  a hidden chat finishing posted one, delivered to Notification Center. The debug app ("Tern Dev") isn't allowed to show

- **Menu bar Open, path checked:** debug control command `reveal ID` runs `main_window::reveal_session` (what
  `tern://session/ID` does). A chat in a hidden tab was brought forward. (Debug `--open-session` does nothing while a
  debug Tern runs: `forward_to_running` returns early in debug builds, an older design, not chat-specific.)

- **Unknown content blocks:** `Transcript::assistant` took a streamed entry's slot before checking the block was one
  it shows, so a block it skips (`redacted_thinking`, a new type) before a reply doubled the reply. Now skipped first;
  test `a_block_it_doesnt_know_is_skipped_without_doubling_the_reply`. Unknown frame types, subtypes and fields are
  ignored; an unknown `control_request` is answered with an error so Claude doesn't wait.

- **Nothing Claude sends is lost (user's rule: show everything, even what isn't parsed):** `Entry::Raw { title, body }`
  (row `chat.raw`, icon file-braces, click shows the JSON) for unknown frame types, `system` subtypes without text,
  stream events, content blocks (assistant and user; `redacted_thinking` too), images it can't draw, tool results with
  no call, control requests it can't answer (still refused/declined so Claude doesn't wait), and lines that aren't JSON
  (`Transcript::apply_line`, consecutive ones merged). Told as notices: any `system` frame with `content` text
  (informational, model refusals, away_summary, scheduled tasks, local_command output), failed hooks, stream `error`,
  `<local-command-stdout/stderr>`, `<bash-stdout/stderr>`, `<task-notification>` (its summary). Shown as the user's:
  `<command-name>` (as `/name args`), `<bash-input>` (as `! cmd`). Citations are listed under a reply. Deliberately
  skipped, by name: `command_lifecycle`, `rate_limit_event`, `keep_alive`, system `status`/`hook_started`/
  `hook_progress`/`turn_duration`/`stop_hook_summary`, successful hooks, `message_delta`/`message_stop`/`ping`,
  `isMeta` and subagent lines, `<system-reminder`/caveats. `commands_changed` now updates the slash list. Saved
  `.jsonl` files feed only `user`/`assistant`/`system` lines (the rest are Claude's storage records). Live stream
  sampled with CLI 2.1.314 (types seen: command_lifecycle, rate_limit_event, system status/hook_*/commands_changed,
  synthetic assistant text for /usage and /context). Checked in the debug app with a crafted history.

- **Protocol inventory (from sdk.d.ts 0.2.92, @anthropic-ai/sdk 0.80 beta types, the 2.1.314 binary, Orca) and what
  followed:** `result` reads `terminal_reason` (`aborted*` = stopped; a real failure shows `errors[]`, max turns/budget
  in words); `rate_limit_event` tells near/reached/clear once per change; `tool_progress` (heartbeat) and system
  `thinking_tokens` (streamed while thinking), `task_progress`, `task_updated`, `background_tasks_changed`,
  `session_state_changed`, `files_persisted`, `elicitation_complete` are skipped by name; notices for `auth_status`,
  `notification` (`text`), `api_retry`, `api_error`, `permission_denied`, `memory_saved`, `stop_hook_summary.hookErrors`,
  task start/notification (`description`/`summary`), compaction with trigger and tokens. Tool results keep their images
  (`Tool.images`, thumbnails in an opened tool row, elements `chat.tool.images`/`chat.tool.image`). Not reachable with
  our `initialize` (no hooks, SDK MCP servers or dialog kinds): `hook_callback`, `mcp_message`, `request_user_dialog`
  (refused + shown). `elicitation` is still declined (no form), shown as a raw row.

- **MCP elicitation forms:** `Entry::Elicit(Elicit { server, message, url, fields, answer })`, fields parsed from
  `requested_schema` (`Field`/`FieldKind`: text, number/integer, boolean, enum/`enumNames`/`oneOf` choice, array of
  choices), required ones marked `*`; `wire::elicit` answers accept+content or decline; replayed answers and
  `control_cancel_request` settle it; `Transcript::waiting()` (and the daemon's `follow`) count it, so the tab is
  Blocked; the daemon notifies "<server> asks for your input". Card `chat.elicit` (text boxes are `InputState`s made
  in `render` by `ensure_form_inputs`; picks in `form_picks`; Submit disabled with "Still wanted: …" in the button row
  so the card's height stays put); URL mode shows the link, Open and Done. Settled forms read as a notice line.
  `tern-chat` turns on serde_json `preserve_order` so fields keep the server's order (a workspace build had it on by
  feature unification, a crate build didn't). Checked end to end with a scratch MCP server
  (`scratchpad/mcp/asker.py`, project `.mcp.json` + `enableAllProjectMcpServers`): the server got
  `{"env":"prod","reason":"hotfix","replicas":2}`, and `{"action":"decline"}` on Decline.
- **Daemon's own fixes:** a turn's end notifies "stopped with an error" only for real failures (`terminal_reason`);
  the daemon binds its socket with `bind_over` at start too, so the socket appears only once it listens (the
  `tern-mux` tests' "Connection refused" flake was this race: they connect as soon as the file exists).

- **MCP forms in history:** the daemon records an elicitation's lines (request, the UI's answer, Claude taking it
  back; `State::form_line`, `ChatHost::record`) as `{"ms","line"}` to `ChatSpec.record` (new, `serde(default)`; also
  in `HandedChat`), which the app sets to `dirs::data()/chats/<session>.jsonl` (`record_path`); `load_history` merges
  them by time (`Transcript::load_with`, `read_record`; lines at/after `before` are left to the replay). Checked: a
  declined form read "asker: you declined" in its place after the tab closed and the session was opened again.
- **Menu bar Open, run for real (debug):** with the debug app quit, `tern --open-session <chat id>` (what the debug
  menu bar's Open runs) launched the app, which adopted the orphan chat into a tab with its conversation. End's
  `close_chat` is what `tests/observer.rs` runs. Clicking the status item itself needs Accessibility for the

## Notes and decisions

- To click through restart/reattach without touching the real session (`~/Library/Application Support/dev.tern`
  is the installed Tern's too): run the bundle's binary with a short scratch `HOME` (a symlink, or the daemon
  socket path is too long) holding symlinks to `~/.claude`, `~/.claude.json`, `~/.local` and
  `~/Library/Keychains` (Claude reads its login through `security`), `ZDOTDIR=$HOME_REAL`, `TERN_SESSION=1`,
  and no folder argument (a folder skips restoring the session). Run `scripts/dev-app-macos.sh` first to copy
  and sign the new build into the bundle. Quit with `key cmd-q` (a kill doesn't save).

- The user's `claude-args` file (`~/Library/Application Support/dev.tern/claude-args`) holds
  `--dangerously-skip-permissions --chrome`. Chats pass the user's args, so they start in Bypass. The mode
  isn't forced at start (`mode_picked`); the mode shown is read from Claude.
- Testing the debug app (see memory `debug-app-screenshots`):

  ```

  printf 'chat-new\n' | nc -U -w 3 target/dev.sock
  ```

  Capture only the debug window by id (`screencapture -l`), never the whole screen.
